| Priority | Enhancement                                 | How                                                                                    | Why                                                                                                                  |
| -------- | ------------------------------------------- | -------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| **P0**   | **Kubernetes Deployment**                   | Deploy the notifier as Kubernetes Deployments and Services.                            | Provides self-healing, rolling updates, service discovery, and enables horizontal scaling.                           |
| **P0**   | **Separate Scheduler & Worker Deployments** | Split the scheduler and workers into independent deployments.                          | Allows worker replicas to scale independently without affecting scheduling.                                          |
| **P0**   | **Leader Election**                         | Use Kubernetes Lease so only one scheduler instance actively polls and schedules jobs. | Prevents duplicate scheduling while maintaining high availability.                                                   |
| **P0**   | **Horizontal Worker Scaling**               | Increase the number of worker pods as event volume grows.                              | Meets the requirement that workers are horizontally scalable according to traffic.                                   |
| **P1**   | **Horizontal Pod Autoscaler (HPA)**         | Scale worker pods automatically based on CPU or custom Prometheus metrics.             | Eliminates manual scaling and adapts capacity to workload.                                                           |
| **P1**   | **KEDA**                                    | Scale worker pods using queue depth or pending delivery metrics.                       | Queue depth is a more accurate indicator of workload than CPU.                                                       |
| **P1**   | **Enhanced Observability**                  | Add Prometheus, Grafana, centralized logging, and distributed tracing.                 | Improves monitoring, troubleshooting, and operational visibility.                                                    |
| **P2**   | **Read Replicas**                           | Route monitoring and reporting queries to PostgreSQL replicas.                         | Reduces read load on the primary database. Limited benefit because the queue is primarily write-heavy.               |
| **P2**   | **Database Sharding**                       | Partition delivery queues by `customer_id` across multiple PostgreSQL clusters.        | Distributes write load when a single primary becomes a bottleneck.                                                   |
| **P3**   | **Kafka Migration**                         | Replace the PostgreSQL queue with Kafka while keeping delivery logic unchanged.        | Provides higher throughput, native partitioning, consumer groups, and improved scalability for very large workloads. |
